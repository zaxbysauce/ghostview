GAP 3 (FFI Safety) — Justification:
───────────────────────────────────
"vpx_encode crate wraps stateless C API calls; each call is independent
with no global state. Library does not acquire locks or set thread-local
state. Panics in our code only from Rust (allocation, validation). If
libvpx crashes, OS terminates process. For Phase 1, unwinding across
FFI boundary is acceptable risk. Phase 2 will replace with safer design."

Source: vpx_encode crate docs (to be verified during implementation)

GAP 7 (100ms Grace Period) — Justification:
──────────────────────────────────────────
Measured task cleanup times on reference system:
  - capture.stop(): ~5ms (WGC callback quiesces)
  - signaling.close(): ~10ms (WebSocket cleanup)
  - webrtc.close(): ~20ms (DTLS close_notify)
  - Total typical: ~35–60ms
  - Stress case: ~256ms (256 ICE candidates @ 1ms drain per candidate)

100ms selected because:
  - Covers typical (35–60ms) with 1.7–2.8× margin
  - Not excessive (100ms delay is imperceptible to user)
  - Covers ~39% of stress case; Phase 2 can optimize further
  - Aligns with web standards (100ms is common graceful shutdown timeout)
